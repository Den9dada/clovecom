# 协议编辑与固件升级

CloveCOM 的协议编辑功能移植自同目录的 clovertls 项目。导航中的“协议编辑”包含解析协议和 Lua 交互协议两种编辑方式。

## 解析协议

支持字段库、字段属性、固定长度和帧尾定界、多个长度覆盖范围、多消息类型、校验、样例生成和 Hex 解析预览。解析协议通过 JSON 导入导出，兼容原项目的版本 1/2/3。导入创建独立草稿；保存后才进入本地协议库。预览在主动测试后生成，修改草稿或 Hex 后失效。

解析协议用于编辑、交换和测试报文结构。固件升级使用交互协议脚本中的收发及流程规则。

## Lua 交互协议

支持新建、重命名、删除、Lua 文件导入导出、行号、语法高亮、缩进、查找替换、撤销重做和错误定位。编辑器内置“接口说明”面板，展示 [宿主 API](development/lua-host-api.md) 和 [Lua 使用说明](development/lua-script-guide.md)。为兼容原项目，脚本头部继续使用 `clovertls-config` 标记。

允许保存存在语法或元信息错误的脚本，便于继续编辑；载入升级前必须通过真实 Lua 解释器校验。导出使用当前草稿内容，不代表保存或校验通过。

协议库保存在应用支持目录下的 `protocols/library.json`，保存采用临时文件写入后替换。协议库预置可编辑的“点表协议—Lua”和“标准 YMODEM—Lua”。已有协议库首次升级到本版时仅补齐一次 YMODEM，不覆盖用户脚本，也不恢复已删除的点表。预置脚本删除后不会重新补回，可从 `assets/protocols/` 导入恢复。

## 升级操作

1. 在“协议编辑 → 交互协议编辑”编写或导入用途为 `upgrade`、支持 `serial` 的脚本，保存。
2. 进入“固件升级”，从“升级交互协议”选择脚本，选择后自动校验并载入一次，固定当前已保存内容。页面重建和脚本库保存不会重复载入；校验期间禁止重复选择。
3. 若脚本声明串口接口初值，应先断开串口再选择协议。初值仅填充一次，之后可在断开状态下调整接口参数。连接中不能修改接口参数。
4. 选择固件并连接串口，点击“开始升级”。成功读完整个固件后才替换当前输入，之后磁盘文件变化不会改变已载入的固件内容。
5. 点击“停止”取消 Lua 流程；进程及在途操作释放后才允许下一次传输，串口连接保留。

保存脚本新版本不会替换升级页已载入内容，页面提示“协议有新版本，请重新选择该协议”。选择载入失败时保留原协议快照，并将选项恢复到实际已载入的协议。已载入或仍在运行的脚本禁止删除，需先停止并点击协议选择框内的“卸载协议”图标解除绑定。未载入 Lua 协议时禁止升级，不提供默认分包发送。升级页不再提供每包字节数或发送间隔，流程参数直接在协议脚本中修改。

Lua 使用当前升级页持有的串口连接和独占传输会话，不另开串口。固件、接收数据、写入、日志和进度都通过宿主接口传递。当前串口适配未提供 RTS/DTR 等运行时控制线接口，脚本要求这些能力时会明确失败。普通交互脚本可以编辑和交换；本次运行接入范围为串口固件升级。

预置点表脚本要求固件至少包含 `42 4C` 魔数开头的 6 字节识别头及 1 字节内容。它由设备主动读取固件，完成判据沿用原项目脚本。

## 标准 YMODEM 升级脚本

选择“标准 YMODEM—Lua”后自动载入，设备切换到 YMODEM 接收模式后开始升级。当前脚本执行单文件批传输，不支持 YMODEM-g。流程参数 `DATA_BYTES`（128 或 1024）、`START_TIMEOUT_MS`、`ACK_TIMEOUT_MS` 和 `MAX_ATTEMPTS` 均直接在脚本中修改，保存后重新选择该协议。

脚本发送 128 字节文件头，携带固件文件名和十进制大小，文件头剩余部分填零；设备以 C 请求 CRC-16/XMODEM，或以 NAK 请求 8 位校验和。数据块默认 1024 字节，尾块填充 0x1A。文件头后等待一次数据阶段请求，后续数据块仅等待 ACK，NAK 或超时原样重传，不改变未确认块的大小或内容，序号按 8 位回绕。

数据发送完毕执行 EOT 握手，兼容直接 ACK 和先 NAK 后 ACK；随后按接收端请求发送空文件名结束块，收到最终 ACK 才报告成功。连续两个 CAN 表示对端取消；失败时尽力发送 CAN CAN，用户停止后宿主会禁止后续写入。

文件名取所选固件的文件名部分并转为小写；文件名不是可用 ASCII 名称或无法装入文件头时，使用 `firmware.bin`，固件内容保持原样。宿主 API 的固件 `display_name` 现在提供实际载入的文件名。

实现依据：[Chuck Forsberg 编订的 XMODEM/YMODEM 协议参考](https://android.googlesource.com/platform/external/syslinux/+/refs/heads/oreo-m6-s2-release/com32/libupload/ymodem.txt)。
## 构建与验证

Windows 应用构建会编译并安装 Lua 解释器、宿主 SDK、许可证、点表及 YMODEM 示例到发布目录的 `lua/`。发布程序执行 Lua 脚本使用随附的运行时，无需额外安装解释器。

开发测试需要先构建 Lua 解释器：

```powershell
cmake -S native/lua_runner -B build/lua_runner -A x64
cmake --build build/lua_runner --config Release
flutter test
flutter build windows --release
```
