# 应用级通信管理与页面收发订阅

## 问题陈述

用户需要在多个页模块中同时使用多个通信连接，并让各模块独立接收、解析和执行任务。目前接口通信页与固件升级页分别持有连接和配置，同一物理串口无法作为一个已打开连接供多个页面共同接收；连接管理、日志、普通发送、文件传输和升级逻辑相互耦合。用户无法在一个位置查看和管理全部连接、接收订阅与发送占用，页面间容易出现重复配置和串口占用冲突。

现有任务还会优先消费原始输入并清空物理收发缓冲，影响其他接收者；同步串口读写可能阻塞界面和其他连接。仅移动配置控件或增加广播流不能满足多连接、独立处理、发送唯一归属和可靠取消的需求。

## 解决方案

建立应用级通信管理，统一持有串口与网卡通信连接、生命周期和收发订阅。标题栏导航折叠按钮右侧增加通信管理入口，打开主窗口内可移动、可调整大小的非模态浮窗。用户在浮窗中配置、打开、断开和删除连接，并管理各页模块的订阅。

各页面移除通信接口配置和连接控件，替换为可订阅通信连接列表，与管理浮窗操作同一份状态。接收和发送分别订阅；同一连接允许多个接收订阅，同时至多有一个发送订阅，一个页面可订阅多个连接。页面发送面向它的全部发送订阅，按目标分别执行和报告结果。

原始接收按页模块与连接独立缓冲和处理，UDP 保留数据报来源和边界。发送经统一资格检查与每连接有界队列执行。多连接升级和文件传输按目标运行独立协议任务；关闭管理浮窗、切换页面和最小化应用不停止通信，停止由明确的订阅、任务和连接操作控制。

## 实现决策

1. 术语以项目领域文档为准：通信接口是本地串口或网卡；通信连接是一份配置及运行状态；串口传输会话是文件收发或升级任务，不能与连接生命周期混用。
2. 遵循 ADR-0001 收拢唯一连接所有权，按已接受的 ADR-0006 建立应用级通信管理；ADR-0004 中基于单连接场景的管理决定已被部分取代，统一传输抽象方向仍有效。遵循 ADR-0005 保持串口和网卡二元接口模型。
3. CommunicationRuntime 作为主要深模块，统一持有配置、稳定连接身份、物理串口占用、连接状态、订阅、发送资格、资源预算与清理。页模块通过受约束的通信入口使用它，不取得原生句柄或底层 transport。
4. 页模块身份稳定，不依赖某个 Widget 实例。数据处理和任务运行与视图呈现分离，页面不可见不注销订阅或取消任务。
5. 管理浮窗与页面订阅列表观察同一份只读状态，经内核命令修改订阅；不能维护各自独立的开关状态再相互同步。发送订阅竞争由唯一权威状态原子裁决。
6. 连接配置与实际运行状态分离；订阅关系与可用状态分离。连接状态表达未打开、打开中、已打开、服务端等待客户端、重连中、关闭中和故障；订阅单独表达接收异常、发送占用与释放中。
7. 串口和网络适配器收拢到统一传输契约。原始输入只有一个应用级事实来源，复用并完善原始包的不可变字节、连接标识、时间、对端和数据报信息，补充链路轮次与顺序标记，避免双套分发产生身份和生命周期分歧。
8. 串口与 TCP 的读取片段不当成完整业务帧；UDP 保留数据报边界、来源及合法空报文，不同对端分别解析，发送目的地继续由配置决定。
9. 接收通道按页模块与连接设置有界缓冲，解析状态按来源隔离；UDP 对端上下文数量、协议任务输入、脚本输入与展示历史也受预算约束。字节和条目容量集中配置，在实现阶段通过压力测试确定默认值，不能暂用无限缓冲。
10. 一个接收者不得修改其他接收者的原始内容。正常容量下完整分发；过载或处理器运行异常后停止对应交付，保留关系并标异常，终止依赖它的双向任务。手动恢复清除旧半包和无效积压，从新数据开始，不补历史，重连不自动解除异常。
11. 区分数据质量问题和处理器故障：普通噪声、坏校验、未知帧由页模块计数并重新同步；不能把每个坏帧当作订阅故障。升级期间其他接收者会看到升级流量，应由其解析规则识别或忽略非目标帧。
12. 不通过暂停订阅而让内部隐式无限缓存。界面批量刷新并限制展示历史，历史截断有可见标记；清空日志只清本页面展示，不清物理缓冲或其他页面状态。
13. 串口 I/O 离开 UI 执行线程，每个串口连接具有独立后台执行能力并独占句柄与资源。读、写和取消能够分别推进，不能把长同步写简单搬到同一执行器后又阻断本连接接收；Future 包装同步等待不视为完成隔离。
14. 重计算或可能长期执行的解析使用可隔离后台执行器。实现须证明慢写、慢解析与解析异常不会阻塞其他订阅者、连接和界面，而不只检查异步方法声明。
15. 普通发送开始时取得页面当前全部发送订阅作为目标，并固化同一份发送内容。操作过程中新增目标不加入，撤销的目标不继续；每个目标入队和实际写出前重新核验身份、订阅版本、链路轮次和可写状态。
16. 权威发送队列按连接设置，由内核统一持有；页模块可保留草稿和协议状态，但不维护可绕过内核的独立待写字节队列。同连接 FIFO，单次内容不交错，不同连接独立推进。
17. 发送队列有容量上限；离线不排队，满队列、超时或不可写明确失败。普通发送和调度层不透明重发整条命令；已有协议规范要求的重传由对应单目标协议任务自行控制，并继续遵守队列与发送资格。
18. 多目标返回逐目标结果和汇总，区分成功、失败、未执行、部分写出或结果不确定。普通发送完成只表示底层接受完整数据；协议成功由任务判断。串口短写和超时不能被解释为零字节已执行，UDP 需核验实际发送结果。
19. 循环发送是启动时确定目标的长期操作，各目标独立调度；新订阅在下次启动加入。同一连接未完成上一轮时不无限产生重叠工作，达不到周期则延后并反映实际状态，不积压历史 tick。目标断开后不自动恢复它的循环。
20. 多连接文件收发、升级按目标创建独立任务与状态，分别处理应答、进度和结果。任务要求目标受功能支持且具备健康的接收订阅和发送订阅；无资格或不支持的目标报告未执行及原因，不阻止合格目标。
21. 任务在首个协议写入前登记原始输入，输入不依赖已经加工的显示数据。任务通道绑定页模块、唯一目标、链路轮次与任务资格；任务内部写入只进入该目标队列，不再次展开到页面全部发送订阅。
22. Ymodem、固件升级与 Lua 宿主写入全部通过任务通道，不直接操作串口。协议原始输入先进入统一分发，不能继续由活动任务截走其他接收者的数据。
23. 同一连接文件传输或升级期间，停止该目标循环并拒绝本页其他手动发送；任务结束不自动恢复循环。任务启动或取消只清私有逻辑缓冲，移除现有共享路径中的物理 RX/TX 清空行为。
24. 撤销发送资格先标释放中并拒绝新写，取消对应任务、循环和未写队列，确认在途写结束或取消完成，再允许新持有者。已经交给驱动的数据无法撤回；停止计时器或 Future 超时不等于底层已停止。
25. 在途写结束无法确认时，显示发送故障或释放中，不能立即继续后续写或转交发送资格；通过确认中止或明确断开完成清理。仍被原生 I/O 使用的资源不得提前释放。
26. 稳定连接身份、链路轮次、发送资格版本与任务身份分别承担配置关联和旧工作隔离。撤销再订阅、断开重连、更换服务端客户端后，旧回调和旧写入不能污染新工作；被取消的打开操作若迟到完成，也需回收其句柄或 socket。
27. 停止双向任务所需接收订阅时终止对应任务；断开连接保留配置和订阅但终止该目标任务，不积压发送。重连只恢复健康订阅的新数据交付，不续跑已终止任务或自动清除处理异常。
28. 仅 TCP 客户端提供可配置运行时自动重连，覆盖首次失败；用户断开取消重试与未完成连接尝试。串口手动重连，TCP 服务端等待下一客户端属于继续监听且仍为单客户端。
29. 持久化连接配置、稳定页模块身份和收发订阅关系。应用重启恢复关系但不打开连接，不恢复任务、发送队列或旧解析状态；运行时自动重连不等于应用启动自动连接。
30. 参数编辑和删除要求连接已完全断开且无打开、重连、关闭操作残留。修改保留订阅并重置新链路的半包；删除移除所有关联订阅；设备缺失显示不可用，不静默替换目标。
31. 管理入口维护单实例非模态浮窗。连接列表显示名称、类型、状态及收发摘要，选中后提供配置和生命周期操作；订阅区域按页模块展示两个方向、占用者和任务状态。页面保留业务处理控件，改用同步的订阅列表展示来源和资格。
32. 界面沿用现有设计令牌与语义事件呈现。遵循 ADR-0003 使用统一浮层系统提示，持久故障通过连接和订阅功能状态保持可见；不重新引入页面内联系统错误横幅。
33. 按唯一所有权、统一数据链、任务迁移、界面替换及恢复能力的顺序推进，保持过渡可验证；不能把页面和内核双重持有连接作为长期方案。现有工作区的其他未提交改动须保留并按最新代码整合。

## 测试决策

1. 主要领域测试入口采用用户已确认的应用级通信模块接口。测试通过真实内核与页模块通信入口提交管理、订阅、发送及任务操作，观察公开状态、交付数据和逐目标结果；不访问私有队列、锁、计时器或原生句柄，不按内部类数量拆分领域测试。
2. 复用既有传输适配器与传输协议回调接合点注入记录型、慢写、短写和失败适配器；按需注入可控时钟与持久化替身。新增的主要业务测试接合点集中在应用级模块，内部执行器不各自暴露测试专用控制面。
3. 所有权与订阅测试覆盖同物理串口重复打开、不同串口共存、多个接收者、唯一发送者、并发申请仅一方成功、释放中禁止新持有者，以及两个 UI 入口观察同一关系。
4. 接收测试从适配器输入原始内容，验证多页完整交付、不可变内容、来源隔离、半包组装、日志清理局部生效、任务不截走监测数据、UDP 多对端和空数据报的边界保留。
5. 故障测试注入慢消费者、缓冲超限和运行异常，验证仅对应页模块与连接故障、关系保留、依赖任务停止、其他订阅继续、重连不解除异常、手动恢复从新数据开始。普通坏帧应计数和重新同步而不误停订阅。
6. 发送测试覆盖目标快照、后加订阅不加入当前操作、撤销后不再写、每目标内容一致、同连接 FIFO、不交错、跨连接独立推进、离线不积压、满队列和超时可见、部分失败汇总与不透明重发。
7. 短写和超时测试验证结果不被误报为零字节执行或完全成功，底层未结束时不能开始后续写或释放给新持有者；测试结果区分本地接受数据与协议级完成。
8. 多目标协议测试使用两台行为不同的模拟设备，验证应答、进度、重传、取消和完成互相独立；一个目标的 ACK 不能推动另一个目标。无接收资格或不支持的目标报告未执行，其他目标继续。
9. 任务协调测试覆盖升级或传输期间拒绝手动发送、停止对应循环、其他接收者仍有原始输入、不调用共享物理清空、任务结束不恢复循环；Lua 与内置协议遵循同一约束。
10. 取消与生命周期测试控制迟到的打开、写完成、接收、协议回调及重连，验证旧工作不进入新轮次或新资格；接收取消、发送撤销、主动断开分别终止正确范围的任务，已结束任务不会在重连后续跑。
11. 持久化测试重建整个应用级运行实例，验证仅恢复配置和订阅，连接未打开、队列为空、任务不运行，缺失设备保留可辨识的不可用状态；删除后不存在悬空订阅。
12. 平台与调度验收需要真实后台执行能力或受控的阻塞适配器，验证慢串口下 UI、其他连接、同连接接收及取消仍能推进。单纯使用已经异步的 fake 不足以证明现有同步 Win32 等待已被隔离。队列默认容量和吞吐目标通过有界压力测试确定。
13. Widget 测试聚焦可见交互：标题栏入口、单实例非模态浮窗、拖动与调整大小、背后页面仍可操作、两个方向开关与占用反馈、旧配置控件移除、逐目标结果、窗口和页面隐藏后继续运行。领域语义继续由应用级接口测试验证，不在所有 Widget 测试中重复实现。
14. 测试先例包括已有的串口连接所有者接口级测试、假传输与协议注入测试、串口传输会话旧任务污染及取消测试、网络本地回环与参数持久化测试、真实 Lua 握手和取消释放测试，以及固件升级与桌面导航 Widget 测试。复用其依赖注入和行为验证方式；现有断言页面独立配置或任务截走输入的测试应更新为本规格行为。
15. 保留网络本地回环、串口真机和真实 Lua 协议的分层联调。硬件测试验证慢写、拔出、取消与多目标升级；与硬件无关的主领域回归通过可控替身稳定运行，失败应能定位到公开契约违约。

## 范围外

- CH341 的 I²C 设备操作接入统一字节通信模型。
- 为文件传输或固件升级新增 TCP、UDP 支持。
- TCP 服务端多客户端、逐客户端订阅与定向发送。
- 串口自动重连、应用启动自动连接、重连后自动恢复已终止任务。
- 自动抢占发送资格，或多个页面同时持有同一连接的发送订阅。
- 管理浮窗升级为独立系统窗口或跨显示器工具窗口。
- 历史原始流落盘重放、离线待发补发、普通命令透明重试、跨连接事务回滚或全目标原子成功。
- 新增通用 Lua 脚本运行产品能力；本规格迁移现有 Lua 升级链路及其宿主收发约束。
- 重写各页面的业务协议、编辑器或日志产品能力；仅完成统一通信所需的接入和隔离。

## 补充说明

- 本规格综合用户已逐轮确认的决定及 2026-11-17 最终确认的数据链方案，不需要重新访谈；测试入口也已包含在整体确认中。
- 普通发送遵循“多发送订阅就多发”；协议任务仅在启动时按多个目标展开，后续通过绑定单个目标的任务通道写入。这两种行为必须同时成立。
- 单一发送订阅隔离发送资格和处理资源，物理设备上的真实流量仍共享；升级期间其他观察页面可能收到非其目标协议的流量。
- ADR-0006 已接受并部分取代 ADR-0004 的单连接前提；统一传输抽象、所有权收拢和既有系统提示约定继续适用。
- 原设计与术语在当前工作区已定稿，但业务实现尚未开始，部分相关代码和文档仍是未提交改动；Issue 应自包含表达要求，不依赖远程尚不存在的本地文档链接。
- 本规格目标分流标签为 ready-for-agent，无需额外分流。
