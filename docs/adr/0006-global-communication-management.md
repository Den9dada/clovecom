# 应用级通信管理与页面按收发方向订阅

状态为已被 [ADR-0008](0008-session-owned-communication.md) 取代。

确认日期：2026-11-17。

通信连接需要被多个页面共享，且同一页面可订阅多个连接。决定由应用级通信内核统一持有物理连接和收发订阅，标题栏非模态管理浮窗与页面订阅列表观察同一份状态；关闭浮窗或页面不可见不改变通信运行。页面移除接口配置及连接控件。

## 权衡与后果

多个接收者需要同时观察原始数据，多个发送者却会产生协议冲突，因此同一连接允许多个接收订阅、至多一个发送订阅。发送资格不自动抢占，撤销时清旧队列并确认在途写结束后才允许新持有者。

页面普通发送面向全部发送订阅，各目标分别执行并报告结果；文件传输和升级按目标创建独立任务，双向任务要求对应连接具有健康的收发订阅，内部写入使用绑定单连接的任务通道。每连接有界 FIFO，不同连接独立推进。发送失败可能已有部分字节送出，不自动重发或承诺全目标原子成功。

原始接收统一分发，页模块按连接独立缓冲和解析，UDP 保留来源与数据报边界。过载或解析异常仅停止对应处理，保留关系并标记异常，由用户手动恢复；其他接收者继续运行。串口 I/O 与重计算离开 UI 执行线程，不能只用 Future 包装同步等待；任务不能清物理 RX 缓冲或绕过发送队列。

断开保留订阅、终止任务，不积压发送或自动续跑任务。重启只恢复配置与订阅，连接不自动打开；仅 TCP 客户端提供可配置的运行时自动重连。通信参数修改和删除均要求已完成断开。

本次统一串口与网卡，文件传输及升级继续仅支持串口，TCP 服务端保留单客户端，CH341 的 I²C 保留原模式。完整设计已获用户确认，作为后续实施依据。

## 与既有决定的关系

本决定取代 [ADR-0004](0004-bytetransport-abstraction-selfowned-manager.md) 中基于单连接场景而不建立应用级多连接管理的部分；保留统一传输抽象方向，不要求整套移植其他仓库的管理器。遵循 ADR-0001 的所有权收拢方向，旧 VM 降为页面适配，避免长期双重连接所有权。
