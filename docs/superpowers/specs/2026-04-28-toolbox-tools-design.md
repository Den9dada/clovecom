# 工具箱模块设计规格

## 目标

在通信助手主界面新增“工具箱”模块，提供面向固件和二进制文件处理的桌面工具工作台。首批工具包括 HEX 文件转 BIN 文件、BIN 文件编辑、BIN 文件拼接。实现时优先支持 Windows 桌面端，保留按钮导入/导出，并增加文件拖拽导入体验。

## 范围

- 在主页主导航新增“工具箱”Tab。
- 工具箱内部使用二级 Tab 切换不同工具。
- 首批实现三个工具：
  - HEX 转 BIN
  - BIN 编辑
  - BIN 拼接
- 抽取通用 HEX/ASCII 查看器、文件导入区、错误提示和工具注册结构。
- 为后续新增工具提供注册式扩展入口。

不在本轮范围内：

- 跨平台拖拽适配。
- 超大文件虚拟滚动优化到专业十六进制编辑器级别。
- 多文件差异比较。
- 校验和、CRC、加密、压缩等额外工具。

## 用户体验方向

工具箱应呈现为安静、紧凑、适合工程调试的桌面工作台。它要延续现有浅色 Material 3 主题和小圆角面板风格，同时让 HEX/ASCII 数据区成为主要工作区域。

核心交互原则：

- 导入入口明显：支持拖拽文件到导入区，也支持点击按钮选择文件。
- 数据预览一致：所有工具都使用同一套 HEX + ASCII 查看器。
- 错误可定位：文件级错误显示在文件行内，操作级错误显示在工具错误区，即时失败通过 SnackBar 提醒。
- 操作可预测：编辑和拼接遇到越界、非法 HEX、地址重叠等情况时停止执行并给出明确原因。
- 扩展简单：新增工具不需要修改工具箱外壳，只需要注册工具定义并提供页面。

## 总体布局

### 主导航

主页顶部新增第四个 Tab：“工具箱”，图标使用工具类图标。主页继续使用 `IndexedStack` 保持页面状态，切换到其他通信模块时，工具箱内已导入文件、编辑数据和拼接片段不应丢失。

### 工具箱外壳

工具箱页面包含二级 Tab：

- `HEX转BIN`
- `BIN编辑`
- `BIN拼接`

二级 Tab 上方或同一行显示当前工具的简短标题和状态摘要。二级 Tab 内容由工具注册表提供，避免在外壳里硬编码每个工具的实现细节。

### 工作台分栏

桌面宽屏布局使用左右分栏：

- 左侧操作栏宽约 320px，放置导入、文件列表、参数、操作按钮、错误状态。
- 右侧数据查看区占据剩余空间，显示当前文件或输出结果的 HEX/ASCII 内容。

窄屏布局改为上下分栏：

- 上方为操作栏。
- 下方为数据查看区。

这种布局保证工具箱在较小窗口下不会出现主要控件重叠或横向溢出。

## 通用组件

### HEX/ASCII 查看器

查看器接受 `Uint8List` 或等价字节列表作为输入，并按固定行宽显示：

- 左侧：8 位十六进制偏移地址。
- 中间：每行 16 个 HEX 字节，大写、两位补齐。
- 右侧：对应 ASCII 字符。

显示规则：

- 可打印 ASCII 范围 `0x20` 到 `0x7E` 直接显示字符。
- 其他字节显示为 `.`。
- 空数据时显示安静的空状态，提示拖入或导入文件。
- 查看器只负责展示，不直接修改数据。

### 文件拖拽导入区

导入区负责统一呈现拖拽和点击导入入口。Windows 桌面端优先支持拖入文件；按钮导入继续使用现有项目中的 `file_picker`。

导入区行为：

- 拖入时显示高亮边框。
- 拖入不支持的扩展名时提示错误。
- 点击导入按钮时按工具声明的扩展名过滤。
- 多文件导入由工具声明是否允许。

### 错误提示

错误分三层：

- 文件行内状态：用于单个文件解析失败、类型不支持等。
- 工具错误面板：显示当前工具最近错误和可操作建议。
- SnackBar：用于导入失败、导出失败、无法访问路径等即时错误。

## HEX 转 BIN 工具

### 输入

支持批量导入：

- `.hex` 文件：按 Intel HEX 格式解析为二进制数据。
- `.bin` 文件：直接读取并预览，用于用户查看或对比。

导入后左侧列表显示：

- 文件名
- 类型
- 文件大小
- 状态：未处理、解析成功、解析失败、已导出

### Intel HEX 解析

解析器作为纯逻辑服务实现，至少支持：

- Data Record `00`
- End Of File Record `01`
- Extended Segment Address Record `02`
- Extended Linear Address Record `04`

校验规则：

- 每行必须以 `:` 开头。
- 字节数、地址、记录类型、数据和校验和必须完整。
- 校验和必须符合 Intel HEX 规则。
- EOF 后不再接受有效数据记录。

地址处理：

- 按记录地址写入输出地址空间。
- 输出 BIN 默认从最小出现地址到最大出现地址连续导出。
- 中间空洞默认填充 `0xFF`。

### 操作

- 选择任一文件后，右侧显示该文件解析或读取后的字节数据。
- “转换当前”导出当前有效 `.hex` 文件为 `.bin`。
- “批量导出”对所有有效 `.hex` 文件逐个导出 `.bin`。
- `.bin` 文件不参与转换，只参与预览。

### 错误

需要明确提示：

- 文件读取失败。
- 非法 HEX 行。
- 校验和错误。
- 不支持的记录类型。
- EOF 缺失或 EOF 后存在数据。
- 没有可导出的 HEX 文件。

## BIN 编辑工具

### 输入

支持导入单个 `.bin` 文件。导入后右侧显示完整字节内容，左侧显示文件名、大小、编辑后大小和是否存在未保存修改。

### 编辑操作

支持三种操作：

- 插入：在指定地址插入 HEX 数据。
- 修改：从指定地址开始覆盖 HEX 数据。
- 删除：从指定地址开始删除指定长度。

输入规则：

- 地址支持十进制和 `0x` 前缀十六进制。
- HEX 数据支持空格、换行、逗号分隔。
- HEX 数据必须由完整字节组成。
- 删除长度支持十进制和 `0x` 前缀十六进制。

边界规则：

- 插入地址允许等于文件长度。
- 修改地址加数据长度不能超过文件长度。
- 删除地址加长度不能超过文件长度。
- 删除长度必须大于 0。

### 操作历史

工具记录最近编辑操作，显示操作类型、地址和影响字节数。支持撤销上一步。撤销只恢复字节内容和未保存状态，不需要实现多级复杂分支历史。

### 导出

导出按钮保存当前编辑后的 `.bin` 文件。导出失败时显示 SnackBar 和错误面板。

## BIN 拼接工具

### 输入片段

拼接工具维护一个片段列表，片段类型包括：

- BIN 文件片段。
- 手动输入 HEX 数据片段。

每个片段包含：

- 名称
- 类型
- 起始地址
- 长度
- 状态

### 拼接规则

- 输出缓冲区根据所有片段的最小地址和最大结束地址生成。
- 空洞区域默认填充 `0xFF`。
- 填充值可配置，必须是单字节 HEX。
- 片段按地址写入输出缓冲区。
- 地址重叠默认报错，不静默覆盖。

### 操作

- 支持拖入或选择多个 `.bin` 文件作为片段。
- 支持新增手动 HEX 片段。
- 支持修改片段地址。
- 支持删除片段。
- 右侧实时预览拼接后的结果；存在错误时显示上一次有效结果或空状态，并明确提示当前错误。
- 导出按钮保存拼接结果为 `.bin`。

## 架构设计

### 目录结构

新增代码按职责拆分：

- `lib/views/toolbox/toolbox_view.dart`：工具箱外壳和二级 Tab。
- `lib/views/toolbox/toolbox_tool_registry.dart`：工具定义和注册表。
- `lib/views/toolbox/widgets/hex_ascii_viewer.dart`：通用 HEX/ASCII 查看器。
- `lib/views/toolbox/widgets/file_drop_zone.dart`：拖拽/点击导入区。
- `lib/views/toolbox/widgets/tool_status_panel.dart`：错误和状态提示。
- `lib/viewmodels/toolbox/hex_to_bin_viewmodel.dart`：HEX 转 BIN 状态。
- `lib/viewmodels/toolbox/bin_editor_viewmodel.dart`：BIN 编辑状态。
- `lib/viewmodels/toolbox/bin_link_viewmodel.dart`：BIN 拼接状态。
- `lib/models/toolbox/toolbox_file_entry.dart`：导入文件条目模型。
- `lib/models/toolbox/bin_edit_operation.dart`：BIN 编辑操作模型。
- `lib/models/toolbox/bin_link_segment.dart`：BIN 拼接片段模型。
- `lib/services/toolbox/hex_parser.dart`：Intel HEX 解析。
- `lib/services/toolbox/hex_text_parser.dart`：用户 HEX 输入解析。
- `lib/services/toolbox/bin_editor_service.dart`：插入、修改、删除纯逻辑。
- `lib/services/toolbox/bin_link_service.dart`：拼接纯逻辑。

### 依赖策略

文件选择继续使用现有 `file_picker`。拖拽导入优先使用 Windows 桌面可用的轻量 Flutter 插件；如果依赖下载或平台限制导致无法接入，则保留拖拽组件接口和点击导入能力，并在实现记录中明确说明限制。

### 状态管理

延续现有项目的 `provider` + `ChangeNotifier` 风格。工具箱外壳不直接持有工具内部业务状态；每个工具页面各自创建 ViewModel，状态边界清晰。

### 纯逻辑服务

文件格式解析、HEX 输入解析、BIN 编辑和 BIN 拼接都放在服务层，不依赖 Flutter UI。这些服务必须可以用 Dart 单元测试直接验证。

## 风险与处理

- 拖拽插件可能需要新增依赖并更新平台工程文件。处理方式是先验证插件兼容 Windows 桌面，再接入；若受限，保持导入区组件接口不变，点击导入仍可完整使用。
- 文件较大时一次性渲染全部行可能影响性能。首版以常见固件文件为目标，查看器使用滚动列表分行构建，后续可升级为虚拟化和分页。
- Intel HEX 地址空间可能非常稀疏。首版以最小地址到最大地址连续导出并使用 `0xFF` 填充，导出前显示输出大小，避免用户误导出异常巨大的文件。
- BIN 编辑容易产生破坏性修改。首版提供未保存状态、操作历史和撤销上一步，减少误操作风险。
