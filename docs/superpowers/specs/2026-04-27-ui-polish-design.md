# UI 优化设计规格

## 目标

在不改变现有功能、数据流和功能范围的前提下，提升通信助手的整体视觉质量。已确认的方向是：浅色专业工作台风格，以串口日志作为视觉中心，并将数据日志区设计成深色终端样式。

## 范围

- 刷新 `lib/main.dart` 中的全局 Material 主题。
- 优化 `lib/views/home/home_view.dart` 中的应用外壳和模块导航表现。
- 调整 `lib/views/serial_port/serial_port_view.dart` 中的串口通信布局与样式。
- 美化 USB 和网络模块的占位页，使其与新的视觉系统保持一致。
- 保留所有现有控件、操作、ViewModel 调用和通信行为。

## 视觉方向

应用应呈现为一个专注、克制、适合长时间使用的桌面调试工具：

- 应用背景使用浅灰色。
- 控制面板使用白色或接近白色的表面，并搭配轻量边框。
- 日志面板使用深色终端风格，让 RX/TX 数据流成为视觉重点。
- 主操作使用蓝色，连接/发送/进度状态使用绿色，断开/停止/错误操作使用红色。
- 标签和控件使用系统 UI 字体；时间戳和数据内容使用等宽字体。
- 间距保持紧凑但不拥挤，适合高频技术操作。

## 布局

### 应用外壳

主页继续保留三个模块：串口通信、USB 通信、网络通信。导航可以继续使用顶部 Tab，但视觉上应比当前的反色 AppBar 更安静、更像工具软件。当前模块需要通过颜色、图标状态或指示线清晰高亮。

### 串口工作台

串口页面从“左侧配置、右侧数据”的平均布局，调整为更强调工作台的数据流布局：

- 顶部保留一条紧凑连接栏，横跨页面，用于端口选择、刷新、波特率和连接/断开。
- 主体区域让日志/数据区占据最大宽度。
- 串口参数、接收配置、发送配置等配置面板移动到辅助侧栏。
- 发送区贴近日志底部，让发送操作更像在终端中输入命令。
- 保留现有区块：串口参数、接收配置、发送配置、文本发送、文件发送、固件升级。

### 数据日志区

日志区应成为页面最强的视觉元素：

- 使用深色背景和轻微边框。
- RX/TX 标签使用不同颜色区分方向。
- 时间戳弱化显示，但仍保持可读。
- 数据内容使用等宽字体。
- 空状态保持安静、居中，避免过度醒目。

### 占位模块

USB 和网络页面仍然是占位功能，不新增功能。它们需要使用与主应用一致的背景、图标样式和字体层级。

## 组件规范

- 通用面板/卡片使用小圆角、轻量边框、低阴影或无阴影。
- 按钮高度和内边距保持一致。
- 输入框使用紧凑但可读的内边距。
- 开关选项避免异常换行，并保留现有文案。
- 发送区内部 Tab 保持功能不变，同时与整体工具风格对齐。

## 行为保持

不得修改以下内容：

- `SerialPortViewModel` 的公开调用方式和状态语义。
- 串口连接、发送、接收、文件发送、固件升级逻辑。
- 现有控制器生命周期。
- 当前模块切换时保留页面状态的行为。
- 输入格式化器和协议选择行为。

## 测试与验证

验证重点：

- 运行 `flutter analyze` 检查静态问题。
- 如果本地 Flutter 环境支持，运行构建或测试命令。
- 如果可以启动桌面端，人工检查串口主界面和占位页面。
- 手动确认现有按钮、开关、下拉框和 Tab 都仍然存在。

## 风险

- 串口视图文件较大，布局调整应分步进行，避免触碰业务逻辑。
- 小窗口下如果侧栏或发送区宽高过于固定，可能出现溢出；实现时应尽量使用响应式约束。
- 控件过度压缩会降低可读性，需要在紧凑和清晰之间保持平衡。
